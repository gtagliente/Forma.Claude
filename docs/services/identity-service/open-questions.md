# identity-service — Open Questions

Consolidates (a) still-open central questions relevant to this service, and (b) new implementation-grounded questions surfaced by reconciling `domain.md`/`architecture.md` against the actual code in `Forma.Auth`.

## Carried from central open items (not this service's to decide alone)

1. **`is_superuser` vs. ADR-001's "no differentiated account roles"** — the `fastapi-users` library bakes in an `is_superuser` boolean on every `User`. Currently only gates the library's own `/users/{id}` routes, plausibly "administers the auth system" rather than a Forma-domain role — but nothing defines that intent explicitly. Not a violation of ADR-001 as far as anyone has decided; flagged so it gets an explicit answer if a real "manage other users" capability is ever requested, rather than silently growing into a role system no one decided on.
2. **Non-human/service account types** (API integrations, premium tiers) — already deferred centrally by ADR-001, no concrete requirement exists. Carried here since this is the service that would eventually build them.

## New, surfaced by reconciling against the existing code (service-loop scope)

3. **Hardcoded JWT/token secret** (`Forma.Auth/app/users.py`, `SECRET = "sakjdhkjad872323"`) — reused for JWT signing, password-reset tokens, and email-verification tokens; not read from `.env` or any environment variable. Real security gap, not a style nit — should be resolved (moved to real secret management) **before** any other service starts trusting tokens issued here, per `architecture.md`'s cross-service integration note. Not fixed in this pass — this is a docs/context bootstrap, not a remediation.
4. **`.env` and `test.db` not gitignored** — `Forma.Auth/.gitignore` only excludes `__pycache__/`, build artifacts, and `.venv`. `.env` currently holds only empty placeholder values, but the pattern itself risks committing real secrets once any exist, and `test.db` is the live SQLite data file.
5. **Dead `Post` relationship** (`Forma.Auth/app/db.py`, `User.posts`) and **unused tutorial dependencies** (`imagekitio`, `streamlit`) — leftover from this codebase's FastAPI-tutorial origin (`pyproject.toml`'s `name = "fastapi-tutorial"`), same shape of debt `exercise-service` had with its Shop/Customer template. Low priority, safe to delete whenever a human confirms it — mirrors `training-planning-service/open-questions.md` #8's stray-file precedent.
6. **No real email delivery** — password-reset and email-verification tokens are only printed to console (`UserManager.on_after_forgot_password`/`on_after_request_verify`). Both flows are otherwise fully wired at the routing layer; nothing reaches a user's inbox today.
7. **No migration tooling** — schema changes apply via `Base.metadata.create_all` (create-if-missing) at startup, not a real migration system. Fine for SQLite/dev; a real gap once the schema needs to evolve against existing data.
8. **No test suite at all** — unlike the .NET services (tests exist but can't run without Docker here), this service has no test framework installed as a dependency yet, period.
9. **Cross-service JWT validation doesn't exist yet** — `exercise-service` and `training-planning-service` both still use a caller-supplied `OwnerId`/`RequestingUserId` stand-in instead of validating a real token from this service. This service now existing doesn't retroactively wire that up; it's the next concrete piece of integration work once someone picks it up, and depends on item 3 being resolved first (no point validating tokens signed with a secret sitting in source control). Distinct from `../../architecture/integration-patterns.md`/[ADR-006](../../architecture/adr/ADR-006-cross-service-reference-integrity.md) (Accepted) — that document governs Exercise↔Workout existence/reference checks specifically, and explicitly named this Identity/`OwnerId` fan-out case as a separate, deferred future instance, predicted to run at far higher call volume than ADR-006's two drivers (every create, in every service) and to be revisited "once `identity-service` is real and its own business rule... is decided" — this pass makes this service real, which is half that trigger; the async/local-cache option ADR-006 deferred for its own drivers may fit this case better than a synchronous point-to-point call, precisely because of that volume difference.

## Status

First real pass, consolidating what's known as of this loop. Item 3 (hardcoded secret) is the one worth prioritizing before anything else here becomes load-bearing for another service.
